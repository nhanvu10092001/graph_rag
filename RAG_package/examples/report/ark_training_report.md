# ARK Model Training & Evaluation Report

## 1. Overview

This report documents the training and evaluation of models for the **ARK (Adaptive Retriever of Knowledge)** multi-agent graph exploration system on the **PrimeKG** biomedical knowledge graph. ARK uses LLM agents that navigate the graph via tool calls (global search, neighborhood exploration, add-to-answer, finish) and aggregates answers across agents using **Voting Rank Fusion**.

Three model families were evaluated:

| Model | Parameters | Training Data | Method |
|-------|-----------|---------------|--------|
| Gemini 3.6 Flash | — (API) | — (zero-shot) | Prompted via Anthropic-compatible proxy |
| Qwen3-4B | 4B | Oracle trajectories | LoRA fine-tuning (full precision) |
| Qwen3-0.6B | 0.6B | Gemini trajectories | QLoRA fine-tuning (INT4 NF4), knowledge distillation |

## 2. Dataset: PrimeKG Trajectories

### 2.1 Oracle Trajectories

Oracle trajectories are deterministic ground-truth paths: the agent follows the shortest path from the question entity to the answer entity in PrimeKG.

| Split | Queries | Trajectories | Answers/Trajectory |
|-------|---------|-------------|-------------------|
| Train | 592 | 592 | 1.0 |
| Val | 199 | 199 | 0.9 |

### 2.2 Gemini Trajectories

Generated by running Gemini 3.6 Flash with 5 parallel agents per query. Each agent independently explores the graph and proposes answers.

| Split | Queries | Trajectories | Avg Steps | Non-Empty (%) |
|-------|---------|-------------|-----------|--------------|
| Train | 592 | 2,840 | 19.6 | 21.2% |
| Val | 199 | 881 | 20.5 | 29.3% |

**Rejection sampling** filters trajectories for distillation: for each query, only the best trajectory (highest Recall@20, fewest steps as tiebreaker) is kept, and only if its Recall@20 > 0.

| Split | Total Queries | Usable Queries | Usable Rate | Training Samples (×3) |
|-------|---------------|----------------|-------------|----------------------|
| Train | 592 | 123 | 20.8% | 369 |
| Val | 199 | 50 | 25.1% | 150 |

Each usable query's best trajectory is tripled to maintain compatibility with the non-rejection-sampling pipeline.

## 5. Evaluation Results

All evaluations use Voting Rank Fusion across agent trajectories on the PrimeKG validation set. Metrics: Hit@K (any correct answer in top-K), Recall@K (fraction of correct answers in top-K), MRR (Mean Reciprocal Rank).

### 5.1 Main Results Table

| Model | Split | Agents | n | Hit@1 | Hit@5 | Hit@10 | Recall@10 | Recall@20 | MRR |
|-------|-------|--------|---|-------|-------|--------|-----------|-----------|-----|
| Oracle (upper bound) | val | 1 | 199 | 0.5879 | 0.5879 | 0.5879 | 0.4511 | 0.4511 | 0.5879 |
| Oracle (upper bound) | train | 1 | 592 | 0.5507 | 0.5507 | 0.5507 | 0.4091 | 0.4091 | 0.5507 |
| Gemini 3.6 Flash | val | 5 | 199 | 0.2060 | 0.2312 | 0.2312 | 0.1788 | 0.1904 | 0.2180 |
| Gemini 3.6 Flash | train | 5 | 592 | 0.1537 | 0.1909 | 0.1943 | 0.1473 | 0.1574 | 0.1693 |
| Qwen3-4B Quantized FT | val | 1 | 20 | 0.2000 | 0.2000 | 0.2000 | 0.2000 | 0.2000 | 0.2000 |
| Qwen3-0.6B Distilled | — | — | — | — | — | — | — | — | — |

### 5.2 Key Observations

1. **Oracle establishes the ceiling**: Hit@1 of ~0.59 on val represents the best achievable performance when the agent follows the exact shortest graph path. The gap between Oracle and all LLM-based agents reflects the difficulty of the graph exploration task.

2. **Gemini 3.6 Flash (teacher)**: With 5 agents and Voting Rank Fusion, Gemini achieves Hit@1 = 0.206 on val — roughly 35% of the Oracle ceiling. The 5-agent ensemble improves Hit@5 to 0.231 (+2.5pp over Hit@1), showing moderate benefit from multi-agent voting.

3. **Qwen3-4B fine-tuned (student, Oracle data)**: Preliminary evaluation on 20 val samples shows Hit@1 = 0.20, matching Gemini's val performance. However, this was evaluated with only 1 agent (vs. Gemini's 5), suggesting the fine-tuned model may be learning useful graph navigation patterns. The small evaluation set (n=20) limits statistical confidence — full evaluation is needed.

4. **Qwen3-0.6B distilled (student, Gemini data)**: Evaluation pending. This model was trained on filtered Gemini trajectories with only 20.8% of training queries producing usable trajectories after rejection sampling.

5. **Train-val gap for Gemini**: Gemini performs better on val (Hit@1 = 0.206) than train (Hit@1 = 0.154), likely reflecting question difficulty distribution rather than data leakage, since Gemini is a zero-shot model.

## 6. Training Pipeline

### 6.1 Architecture

The training pipeline uses **TRL's SFTTrainer** with **PEFT LoRA** adapters:

```
Base Model (Qwen3-4B / 0.6B)
    └── LoRA Adapters (r=32, alpha=64)
        ├── q_proj, k_proj, v_proj, o_proj  (attention)
        └── gate_proj, up_proj, down_proj   (MLP)
```

**Assistant-only loss**: Only assistant (model output) tokens contribute to the loss; system prompts, user messages, and tool results are masked with label=-100.

### 6.2 Knowledge Distillation Flow

```
PrimeKG Questions (592 train / 199 val)
    │
    ▼
Gemini 3.6 Flash (5 agents × N questions)
    │
    ▼ (2,840 train / 881 val trajectories)
    │
Rejection Sampling (Recall@20 > 0, best per query)
    │
    ▼ (123 train / 50 val usable queries, ×3 = 369/150 samples)
    │
QLoRA Fine-Tuning on Qwen3-0.6B
    │
    ▼
Distilled Qwen3-0.6B (eval_loss = 0.368)
```

### 6.3 Key Design Decisions

- **Rejection sampling** eliminates trajectories where the agent found no correct answers, preventing the student from learning failure patterns. The aggressive filter (20.8% retention) trades dataset size for trajectory quality.
- **3× duplication** of accepted trajectories compensates for the reduced dataset after rejection sampling, maintaining training batch diversity.
- **QLoRA (INT4)** for Qwen3-0.6B enables training on consumer GPUs while maintaining model quality through double quantization with NF4 data type.
- **Full-precision LoRA** for Qwen3-4B — the larger model uses gradient checkpointing instead of quantization for better training dynamics.
- **Effective batch size = 16** for both models (4×4 for Qwen3-4B, 1×16 for Qwen3-0.6B), balancing memory constraints with gradient stability.
