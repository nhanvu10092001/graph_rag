\section*{Executive Abstract}
\addcontentsline{toc}{chapter}{Executive Abstract}

Standard Retrieval-Augmented Generation (Naive RAG) systems based on flat chunking and vector space similarity (e.g., Cosine Similarity over high-dimensional embeddings) suffer from two fundamental bottlenecks: (1) \textbf{Global Context Fragmentation}, causing failures in answering corpus-wide macro-summarization queries; and (2) \textbf{Multi-Hop Reasoning Failures}, which prevent LLMs from traversing complex dependency chains across disparate documents. This report presents \textbf{HLG LLM Utils}, a modular, production-grade Graph RAG framework built on a Python monorepo architecture (\texttt{uv workspaces}).

Our framework introduces key contributions in Knowledge Representation and Information Retrieval:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Formal Property Knowledge Graph Modeling:} Automated extraction of entities ($\mathcal{E}$), relationships ($\mathcal{R}$), and attributes from unstructured text, persisting them onto a Neo4j Property Knowledge Graph.
    \item \textbf{Hierarchical Leiden Community Detection:} Partitioning the entity graph into multi-level community hierarchies, combined with parallel Map-Reduce LLM summarization for Global Search queries.
    \item \textbf{Cypher Query Self-Correction State Machine:} A LangGraph state machine translating natural language queries into executable Cypher statements, featuring a 3-iteration error feedback loop against Neo4j execution logs.
    \item \textbf{ARK Autonomous Multi-Agent Exploration:} Implementing the ACL 2026 Adaptive Retriever of Knowledge algorithm to dynamically adjust breadth-depth graph traversal with Voting Rank Fusion (VRF).
\end{enumerate}

This report comprehensively details the system architecture, core algorithms, and end-to-end integration workflows of the HLG LLM Utils framework.

\textbf{Keywords:} Graph RAG, Knowledge Representation, Hierarchical Leiden Algorithm, Cypher Self-Correction, Multi-Agent Systems, LangGraph, FastMCP.

\chapter{Introduction \& Problem Statement}
% =============================================================================

\section{Background \& Motivation}
In the era of Large Language Models (LLMs), natural language understanding and generation have reached unprecedented levels. However, standalone LLMs remain susceptible to hallucinations and knowledge cutoff constraints because their knowledge is statically encoded within model parameters. Retrieval-Augmented Generation (RAG) emerged as the dominant paradigm to ground LLM responses in external authoritative data sources.

Despite its initial success, Naive RAG—which relies on sliding-window text chunking and vector space cosine similarity—exhibits severe structural limitations when applied to complex enterprise Knowledge Representation tasks.

\section{Limitations of Naive Flat RAG}
Through theoretical analysis and empirical observations, we identify three critical failure modes of Naive RAG:
\begin{enumerate}
    \item \textbf{Structural Context Fragmentation:} Fixed-size chunking (e.g., 1,000 tokens) severs conceptual relationships spanning across different paragraphs or separate documents.
    \item \textbf{Multi-Hop Reasoning Blindspots:} When answering queries requiring multi-step relational chains ($A \to B \to C$), vector similarity retrieves chunks mentioning $A$ or $C$, but misses the crucial intermediate link $B$.
    \item \textbf{Corpus-Wide Global Search Failures:} Vector similarity fails on high-level thematic queries (e.g., *"What are the primary overarching themes in this document collection?"*), as query embeddings do not align with any single text segment.
\end{enumerate}

\section{Research Objectives \& Core Contributions}
To address these limitations, this project designs and implements \textbf{HLG LLM Utils}, an advanced Graph RAG framework combining Property Knowledge Graphs (PKGs) with multi-agent coordination and hierarchical community detection.

Our primary contributions include:
\begin{itemize}
    \item Formalizing Property Knowledge Graph schemas $G = (V, E, \mathcal{L}_V, \mathcal{R}_E, \Phi_V, \Phi_E)$ in Neo4j.
    \item Implementing Hierarchical Leiden Community Detection for corpus-wide Map-Reduce Global Search.
    \item Building a LangGraph Cypher Query Self-Correction State Machine with automatic error recovery.
    \item Integrating the ACL 2026 ARK (Adaptive Retriever of Knowledge) multi-agent trajectory exploration engine.
    \item Engineering a modular monorepo architecture (\texttt{uv workspaces}) decoupling core utilities, vector stores, graph pipelines, and MCP interfaces.
\end{itemize}

\chapter{Theoretical Foundations \& Related Work}
% =============================================================================

\section{Knowledge Representation Paradigms}
Knowledge Representation (KR) investigates formalisms for encoding real-world domain knowledge into computational structures capable of reasoning \cite{ji2022survey}.

\subsection{From Semantic Networks to Property Knowledge Graphs}
The evolution of KR spans Semantic Networks \cite{quillian1968semantic}, Minsky's Frame Systems \cite{minsky1974frame}, Description Logics \cite{baader2003description}, and Semantic Web standards (RDF/OWL). Property Knowledge Graphs (PKGs) have emerged as the industrial standard, allowing key-value properties to be attached directly to vertices and directed edges.

\section{Vector Space Embeddings \& Hybrid Retrieval}
Dense vector embeddings map text segments into continuous vector spaces $\mathbb{R}^d$ \cite{reimers2019sentencebert}. To maximize retrieval precision, our system employs Reciprocal Rank Fusion (RRF) \cite{cormack2009rrf} to combine lexical BM25 scores \cite{robertson2009bm25} with dense vector and graph scores:
\begin{equation}
RRF(d \in D) = \sum_{m \in M} \frac{1}{k + r_m(d)}
\end{equation}
where $M$ denotes retrieval modalities, $r_m(d)$ is the document rank, and $k = 60$ is the smoothing constant.

\section{Community Detection \& The Leiden Algorithm}
Partitioning complex networks into cohesive modules enables macro-level context extraction. The Leiden algorithm \cite{traag2019leiden} guarantees well-connected communities by introducing a local sub-community refinement step missing in Louvain. The modularity quality function $\mathcal{H}$ is defined as:
\begin{equation}
\mathcal{H} = \frac{1}{2m} \sum_{ij} \left( A_{ij} - \gamma \frac{k_i k_j}{2m} \right) \delta(\sigma_i, \sigma_j)
\end{equation}
where $A_{ij}$ is the adjacency matrix, $k_i, k_j$ are node degrees, $m$ is the total edge weight, $\gamma$ is the resolution parameter, and $\delta(\sigma_i, \sigma_j) = 1$ when nodes share a community.

\section{Microsoft GraphRAG \& ARK Exploration}
Recent work by Microsoft Research \cite{edge2024graphrag} demonstrated the efficacy of hierarchical community summarization for global queries. Furthermore, the ARK framework \cite{polonuer2026ark} established autonomous agentic graph exploration balancing breadth (\texttt{global\_search}) and depth (\texttt{neighborhood\_exploration}).

\section{Property Knowledge Graph Formalization}
We formally model the Property Knowledge Graph $\mathcal{G}$ as a 6-tuple:
\begin{equation}
\mathcal{G} = \left( V, E, \mathcal{L}_V, \mathcal{R}_E, \Phi_V, \Phi_E \right)
\end{equation}
where $V$ is the set of entity vertices, $E \subseteq V \times \mathcal{R}_E \times V$ is the set of directed typed edges, $\mathcal{L}_V$ represents node labels, $\mathcal{R}_E$ contains relationship types, and $\Phi_V, \Phi_E$ map property key-value attributes onto vertices and edges.

The graph edges enforce structural integrity:
\begin{align}
(d:\text{Document}) &\xrightarrow{\text{HAS\_CHUNK}} (c:\text{Chunk}) \\

(e_1:\text{Entity}) &\xrightarrow{\text{RELATED\_TO} \{\text{description, weight}\}} (e_2:\text{Entity}) \\
(e:\text{Entity}) &\xrightarrow{\text{BELONGS\_TO} \{\text{level}\}} (c:\text{Community}) \\

\end{align}

\section{Hierarchical Leiden Community Detection}
The Hierarchical Leiden Algorithm partitions entity graph $G$ across levels $l \in [0, L_{\max}-1]$:

\begin{center}
\fbox{
\begin{minipage}{0.92\textwidth}
\vspace{0.2cm}
{\bfseries\color{navyblue}Algorithm 1: Hierarchical Leiden Partitioning and Summarization}\\[0.2cm]
\small
\textbf{Input:} Entity Graph $G = (V, E, W)$, Base resolution $\gamma_0$, Max levels $L_{\max}$\\
\textbf{Output:} Hierarchical Community Tree $C_{tree}$ summarized by LLM\\[0.2cm]
1: $G_{current} \leftarrow G$\\
2: \textbf{for} $l = 0$ \textbf{to} $L_{\max} - 1$ \textbf{do}\\
3: \quad $\gamma_l \leftarrow \gamma_0 \times (0.5)^l$\\
4: \quad $P_l \leftarrow \text{FindPartitionLeiden}(G_{current}, \gamma_l)$\\
5: \quad $P_{refined} \leftarrow \text{RefineSubCommunities}(G_{current}, P_l)$\\
6: \quad \textbf{foreach} Community $c \in P_{refined}$ \textbf{do}\\
7: \qquad $SubGraph \leftarrow \text{ExtractEntitiesAndEdges}(G, c)$\\
8: \qquad $Report \leftarrow \text{LLM\_Summarize}(SubGraph)$\\
9: \qquad $\text{SaveToNeo4j}(c, l, Report.title, Report.summary, Report.findings)$\\
10: \quad $G_{current} \leftarrow \text{AggregateGraph}(G_{current}, P_{refined})$
\vspace{0.2cm}
\end{minipage}
}
