Downstream Evaluation Results

Qwen3-4B Fine-tuned — Agent Behavior Analysis

Setup: Merged INT4 model on RTX 3070, val split, 20 questions, max 30 steps, 1 agent. Avg 38.6s per question.

Tool-calling pattern learned. Model consistently uses a 3-step trajectory: search_in_graph → add_to_answer → finish
Efficient execution. Exactly 3 steps per question (vs. Oracle multi-hop). Most questions return 5 answer nodes.
Single-hop limitation. Model performs only one search — no multi-hop graph exploration. This explains the gap vs. Oracle (0.200 vs 0.588 Hit@1).
Hit@1 matches Gemini Flash (0.200 vs 0.201) despite being ~10× smaller, but Gemini achieves better Hit@5 (0.226 → 0.340) through multi-hop reasoning.
Token accuracy ≠ downstream accuracy. 98.6% training token accuracy yielded only 20% Hit@1 — the model memorized the pattern but not the reasoning.

Recommendations

Qwen3-4B — Improvements

Multi-hop training data. Current oracle trajectories may be too short. Include trajectories with get_neighbors exploration steps.
Diverse trajectories. Train with multiple trajectory styles per question — not just shortest-path oracles.
Full val set evaluation. Run on all 199 val questions for statistically significant comparison (current n=20 has high variance).

Qwen3-0.6B — Action Required

Re-train for 3 epochs (~110 steps with batch=16, grad_accum=4) matching the 4B training recipe.
After training converges, evaluate on the same val subset to compare 0.6B vs 4B downstream performance.
0.6B has lower capacity — may need more multi-hop data and longer training to bridge the gap.
